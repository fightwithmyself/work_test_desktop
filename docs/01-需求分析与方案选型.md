## 2. 用户与使用场景分析

目标用户:不懂命令行的普通用户。典型场景:

1. 手机、相机拍的 MOV/MKV 要转成 MP4 发给别人或上传。
2. 视频太大,想压缩体积。
3. 从视频里提取音频。
4. 一次处理一批文件。
5. 做个短 GIF。

对"给人用"的含义的推导:

- **零配置可用**:不能要求用户自己装 ffmpeg 并配环境变量。
- **少选择**:默认给预设,高级参数折叠。
- **看得见状态**:每个任务有清晰状态(等待、转换中、完成、失败、已取消)和进度。
- **出错说人话**:不能直接把 ffmpeg 原始报错甩给用户。
- **不丢文件**:默认不覆盖原文件、不覆盖同名输出。
- **可中断**:任何时候能取消,取消后不留半成品。

## 3. 功能清单与取舍

### P0 必做
- 拖拽/选择导入(多文件)
- ffprobe 信息展示
- 缩略图(ffmpeg 抽帧)
- 格式转换(MP4/MKV/WebM/MOV/AVI/GIF/MP3/AAC)
- 预设 + 高级参数
- 实时进度、取消
- 输出目录选择、同名保护

### P1 优化(每项的价值)
| 优化项 | 用户价值 | 成本 |
|---|---|---|
| 内置 ffmpeg | 零配置 | 低 |
| 任务队列(并发=1 可调) | 批量处理不卡机器 | 中 |
| 命令预览(可复制) | 透明、可排错、体现"命令行驱动" | 低 |
| 输出体积预估 | 避免转完才发现更大 | 低 |
| 硬件编码检测(NVENC/QSV/AMF) | 速度提升数倍 | 中 |
| 错误信息人话化 | 降低失败时的挫败感 | 中 |
| 完成通知 + 打开所在文件夹 | 闭环体验 | 低 |
| 设置持久化 | 少重复操作 | 低 |

### 明确不做(防止范围膨胀)
- 视频剪辑、字幕烧录、滤镜特效
- 云端转换、账号体系
- 接入 ffmpeg API(题目也明确不要求)

## 4. 非功能需求

| 维度 | 要求 |

| 三天内交付把握(环境+开发效率) | 25% | 5 | 3 | 4 | 1 | 2 | 3 / 3 |
| 界面精致度与"给人用"体验 | 20% | 5 | 4 | 3 | 5 | 4 | 3 / 2 |

| 打包分发(安装包/体积) | 10% | 4 | 4 | 3 | 5 | 4 | 4 |

### 6.3 逐方案结论

**A. Electron + React + TS**
- 优点:环境已具备;界面开发最快、最精致;Node `child_process` 管理 ffmpeg 子进程成熟;测试生态完整。
- 风险:被质疑"本质是网页";安装包体积较大(约 80-150 MB)。
- 缓解:用到原生能力(系统文件对话框、拖拽、托盘/任务栏进度、系统通知、单实例、打开文件夹),文档里把"为什么这是客户端"讲清楚。

**B. Qt 6 + C++17**
- 优点:客户端属性最强;体积小;`QProcess` 贴合需求;可静态/`windeployqt` 打包。
- 风险:需装编译器 + CMake + Qt(都要放到 F 盘),Qt 下载体量大;样式美化耗时;三天内 C++ 调试成本偏高。
- 缓解:Day 1 前 30 分钟做环境验证(Hello Window + 调通 `QProcess`),失败则回退。

**C. PySide6**
- 优点:Python 已具备,装一个 pip 包即可;开发快。
- 风险:打包(PyInstaller)体积与杀软误报;界面美观度需要额外投入;启动较慢。

**D. Tauri**:没有 Rust,需要装 Rust + MSVC Build Tools(体积大,且依赖 C 盘的概率高),三天风险过大,淘汰。

**E. WPF/WinUI**:本机只有 x86 的 dotnet 运行时,SDK 状态未知,且只限 Windows,淘汰。

**F. wxWidgets / ImGui**:生态与界面表现不适合"给人用"的目标,淘汰。

### 6.4 收敛为两条候选

| | 方案 A:Electron | 方案 B:Qt 6 + C++ |
|---|---|---|
| 一句话 | 稳妥、好看、快 | 最"客户端"、更硬核、风险更高 |
| 环境准备 | 几乎为零(仅下载依赖,缓存放 F 盘) | 装 MinGW/CMake/Ninja/Qt,预估 2-5 GB,全放 F 盘 |
| Day 1 能交付 | 导入 + 信息 + 缩略图 | 环境 + 导入 + 信息(缩略图可能顺延) |
| 最大风险 | 被认为"不够原生" | 环境或编译问题吃掉工期 |
| 回退成本 | 低 | 回退到 A 需重做,先验证环境可降低此风险 |
| 适合的情形 | 重点体现 AI 工程效率与完整交付 | 目标岗位偏 C++ / 桌面原生 |

## 7. 推荐

1. **默认推荐 A(Electron + React + TS)**:加权得分最高,交付把握最大,最能保证"给人用且经过测试"。
2. **如果目标岗位偏客户端/C++,推荐"B,先验证环境"**:先在 F 盘装好工具链并跑通 Hello Window + `QProcess` 调 ffmpeg,约 30-60 分钟见分晓,通过则走 Qt,否则回退 A。

## 8. 环境搭建原则(F 盘约束)

- 所有新装工具放 `F:\agent_study\tools\`(或 `F:\devtools\`)。
- 通过环境变量把缓存定向到 F 盘:`npm_config_cache`、`ELECTRON_CACHE`、`ELECTRON_BUILDER_CACHE`、`TEMP/TMP`、`PIP_CACHE_DIR` 等。
- Node 依赖使用 npmmirror 镜像,Electron 二进制使用 `ELECTRON_MIRROR`。
- 每安装一个工具,记录路径与版本到 `docs/ENVIRONMENT.md`,保证可复现。
- 安装前先报告预估体积,避免占满 C 盘。
