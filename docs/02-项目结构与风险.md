## 2. 总体架构

```
┌──────────────────────── Renderer(React,沙箱,无 Node 能力)────────────────────────┐
│  视图层:FileList / VideoCard / SettingsPanel / CommandPreview / TaskQueue / Toast │
│  状态:zustand store(files、tasks、settings)                                       │
│  只通过 window.api(preload 暴露的最小接口)与主进程通信                          │
└───────────────▲───────────────────────────────────────────────────────────────────┘
                │ contextBridge + ipcRenderer.invoke / on(类型安全的通道表)
┌───────────────┴──────────────── Preload(受信桥)────────────────────────────────────┐
│  暴露:probe / thumbnail / convert 控制 / 设置 / 系统能力 / webUtils.getPathForFile │
└───────────────▲───────────────────────────────────────────────────────────────────┘
                │
┌───────────────┴──────────────── Main(Node)────────────────────────────────────────┐
│  ipc/ 参数校验层  →  services/ 业务服务  →  core/ 纯逻辑(可单测)                  │
│  services: locator → probe / thumbnail / hwaccel / queue → converter → process     │
└─────────────────────────────────────────────────────────────────────────────────────┘
                │ child_process.spawn(数组参数,不经 shell)
            ffmpeg.exe / ffprobe.exe
```

**分层原则**
1. `core/` 是纯函数,**不依赖 electron 和 fs**,保证能用 Vitest 秒测。
2. `services/` 有副作用(进程、文件、系统),通过接口注入依赖,测试时可替换。
3. `ipc/` 只做"校验 + 转发",不写业务逻辑。
4. 渲染层不直接 import `main/` 的任何代码;`core/` 与 `shared/` 可以被两侧共享(命令预览、体积预估在渲染层本地实时计算,但参数构建与主进程**用同一份代码**,避免预览与实际执行不一致)。

## 4. 关键模块设计

### 4.1 IPC 通道(类型化)
| 通道 | 方向 | 作用 |
|---|---|---|
| `probe:file` | R→M invoke | 返回 VideoInfo 或结构化错误 |
| `thumb:get` | R→M invoke | 返回缩略图(小 JPEG 的 data URL,不暴露本地文件路径) |
| `thumb:strip` | R→M invoke | 悬停预览的多帧雪碧图 |
| `convert:enqueue` | R→M invoke | 入队,返回 taskId |
| `convert:cancel` / `convert:retry` / `queue:pause` / `queue:resume` | R→M invoke | 任务与队列控制 |
| `convert:preview-command` | 渲染层本地计算 | 复用 `core/args-builder` |
| `task:update` | M→R 事件 | 状态/进度/速度/ETA 推送(节流,约 4~10 次/秒) |
| `settings:get/set` | R→M invoke | 设置读写 |
| `system:reveal` / `system:pick-output-dir` / `system:pick-files` | R→M invoke | 原生对话框与资源管理器 |
| `hw:capabilities` | R→M invoke | 可用硬件编码器列表 |

### 4.2 任务状态机
```
queued ──start──▶ running ──ok──▶ done
   │                 │──error──▶ failed ──retry──▶ queued
   │                 └─cancel──▶ canceled
   └─cancel──▶ canceled
```
- **队列暂停**:仅停止拉起新任务,不暂停正在运行的 ffmpeg(见 D-003 补充)。

### 4.3 转换任务生命周期(避免半成品)
1. 计算最终输出路径(同名自动加 ` (1)`)。
2. ffmpeg 写入**同目录临时文件**(保留扩展名,如 `name.__part__.mp4`)。
3. 成功 → 原子改名为最终文件;失败/取消 → 删除临时文件。
4. 应用启动时清理上次异常退出遗留的临时文件(记录在 userData 的日志里)。

### 4.4 取消流程
先向 ffmpeg stdin 写 `q`(优雅停止) → 等 ~1.5 秒 → 超时则 `taskkill /PID <pid> /T /F` 杀整棵进程树 → 清理临时文件 → 状态置 `canceled`。

### 4.5 进度
`ffmpeg -progress pipe:1 -nostats`,读取 `out_time_us`,用探测得到的时长计算百分比。时长缺失(部分 MKV/WebM/损坏文件)→ 显示"不定进度"+ 已处理时长,不显示假百分比。

### 4.6 硬件加速
1. 从 `ffmpeg -encoders` 找候选(`h264_nvenc`、`hevc_nvenc`、`h264_qsv`、`h264_amf` 等)。
2. **对每个候选做真实小样本编码**(`lavfi` 生成 256×256 的 0.1 秒黑帧编码到 `null`),成功才算可用 —— 编码器出现在列表里不代表显卡真能用。
3. 启动后台探测并缓存;转换时若硬件编码失败,**自动回退软件编码重试一次**并提示用户。

### 4.7 缩略图
- 默认取时长 10% 处一帧(避开黑屏首帧),缩放到 320 宽,JPEG。
- `-ss` 放在 `-i` 前(快速定位)。极短视频(< 1 秒)取第 0 帧。
- 无视频流(纯音频)→ 用占位图,不报错。
- 悬停预览:一次 ffmpeg 调用抽 N 帧拼成雪碧图,避免每次悬停都起进程。

### 4.8 预设(初版)
| 预设 | 容器 | 视频 | 音频 | 备注 |
|---|---|---|---|---|
| 通用兼容 | MP4 | H.264 CRF 23 | AAC 160k | 默认 |
| 高压缩 | MP4 | H.265 CRF 28 | AAC 128k | 体积更小,老设备兼容性较差(界面提示) |
| 网页友好 | WebM | VP9 CRF 32 | Opus | |
| 小体积分享 | MP4 | H.264 720p CRF 28 | AAC 96k | |
| 保留画质 | MKV | H.264 CRF 18 | 音频直拷贝 | |
| 动图 | GIF | palettegen/paletteuse,限宽、限帧率 | — | |
| 提取音频 | MP3 / AAC | — | 192k | |
| 仅换封装(极速) | 目标容器 | `-c copy` | `-c copy` | 不重新编码,秒级,编码不兼容时自动提示 |

### 4.9 原生桌面能力(回应"客户端关联度")
系统文件选择/保存对话框、拖拽文件、任务栏进度条、系统通知、"在资源管理器中显示"、单实例与二次打开传参、窗口状态记忆、关闭时有任务运行的确认提示、菜单与快捷键(Ctrl+O 导入、Esc 取消等)。

## 5. 安全基线
- `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`。
- 严格 CSP;`will-navigate` 与 `setWindowOpenHandler` 一律拒绝;不加载远程内容。
- 所有 IPC 载荷在主进程校验(路径为绝对路径且存在、枚举值白名单、数值范围)。
- 只用 `spawn(file, argsArray)`,**绝不使用 `shell: true` 或字符串拼接命令**。
- 渲染层拿不到文件系统路径以外的 Node 能力;缩略图以 data URL 传递。

## 7. 风险与注意点

按"发生概率 × 影响"排序,**标 ★ 的是我在本机已核实或已知必踩的**。

| 编号 | 风险 | 影响 | 对策 |
|---|---|---|---|
| ★R-01 | **C 盘仅剩 1.6 GB**,npm 全局前缀在 C 盘,Electron/electron-builder/Playwright 等默认缓存可能写 C 盘 | 安装中途写满 C 盘,系统异常 | 不做全局安装;`scripts/env.ps1` 显式设置 `ELECTRON_CACHE`、`ELECTRON_BUILDER_CACHE`、`npm_config_cache`(已在 F)、`PLAYWRIGHT_BROWSERS_PATH`、TEMP(已在 F);安装前后检查 C 盘余量 |
| ★R-02 | **远程仓库不是空的**,已有含 `README.md` 的 Initial commit | 首次 push 被拒绝(non-fast-forward) | 本地先 `git init`,`git pull origin main --allow-unrelated-histories` 合并,保留/覆盖其 README 后再 push;**不使用 `--force`** |
| ★R-03 | **Electron 新版本移除了 `File.path`**,拖拽拿不到文件路径 | 拖拽导入失效 | 在 preload 使用 `webUtils.getPathForFile(file)`;E2E 覆盖拖拽 |
| ★R-04 | **ffmpeg 二进制在 asar 内无法执行** | 打包后"开发能跑,安装后不能用" | `asarUnpack` 解包 ffmpeg/ffprobe;`ffmpeg-locator` 把 `app.asar` 路径替换为 `app.asar.unpacked`;`verify-package.ps1` 在打包产物上实测 |
| ★R-05 | **ffmpeg-static 安装时从 GitHub 下载二进制**,可能慢或失败 | `npm install` 卡住 | 设置 `FFMPEG_BINARIES_URL` 指向 npmmirror 镜像;失败时手动下载放到 F 盘并指向 |
| ★R-06 | **electron-builder 在 Windows 上解压 winCodeSign 需要创建符号链接**,无管理员/开发者模式会报错 | 打包失败(经典坑) | 设置 `win.signAndEditExecutable: false`(不做代码签名,本就用不到);或开启 Windows 开发者模式;使用 `ELECTRON_BUILDER_BINARIES_MIRROR` 镜像 |
| R-07 | 内置 ffmpeg 的 **GPL 许可证**(含 libx264/libx265) | 分发合规问题 | README 与关于页注明 ffmpeg 来源、版本与许可,并附上游链接;本项目为笔试作品,不用于商业分发 |
| R-08 | 内置 ffmpeg **可能不含某些编码器**(如 NVENC/AMF/某些音频编码) | 预设失败 | 启动时探测可用编码器,预设按可用性降级或置灰,不让用户选到必失败的选项 |
| R-09 | 编码器出现在 `-encoders` 里 ≠ 显卡真能用 | 硬件加速"假可用" | 真实小样本编码验证 + 转换失败自动回退软件编码 |
| R-10 | Windows **没有简单可靠的暂停进程方式**;终止进程不彻底会留下孤儿 ffmpeg | 误导用户/占 CPU | 不做进程级暂停,只做队列暂停;取消用 `q` + `taskkill /T /F`;应用退出钩子统一清理;启动时清理遗留临时文件 |
| R-11 | **路径中的中文、空格、`'`、`[]`、`%`、超长路径(>260)** | 转换失败或找不到文件 | 全程数组传参;文件路径**不放进滤镜字符串**;输出名清洗非法字符;用中文/空格/特殊字符样本做集成测试;超长路径给出明确提示 |
| R-12 | 视频元数据**不可信**:时长 N/A、无音轨、旋转元数据、可变帧率、多音轨/字幕轨、纯音频、封面图流 | 信息显示错误、进度假、转换后画面旋转错误 | probe 解析层对每个字段容错;进度退化为不定进度;默认保留首条视频流+首条音频流并可选;用样本集覆盖 |
| R-13 | **进度解析不准或刷新过密**导致界面卡顿 | 体验差 | 使用 `-progress pipe:1` 机读格式;主进程节流后再推送;列表使用稳定 key,避免整表重渲染 |
| R-14 | **同名覆盖、输出到源文件所在位置、磁盘空间不足、目录无写权限** | 数据丢失或失败不明 | 默认不覆盖(自动加后缀);输出与输入同一路径时拒绝;启动转换前检查可写与大致空间;错误翻译成人话 |
| R-15 | **体积预估不准**(CRF 模式本质不可精确预估) | 误导用户 | 只在码率模式给"较准"值,CRF 模式给范围并明确标"约/仅供参考"。不假装精确 |
| R-16 | **打包产物体积大**(ffmpeg 约百兆级)、GitHub 单文件 100 MB 限制 | push 被拒绝 | 安装包与 `release/`、`node_modules`、测试视频一律 `.gitignore`;安装包走 GitHub Release 或网盘,不进 git 历史 |
| R-17 | **未签名安装包被 SmartScreen 警告** | 审核者以为有毒 | README 说明原因与"仍要运行"的步骤;同时提供免安装 zip |
| R-18 | **ESM/CJS 与打包兼容性**(Electron 主进程对纯 ESM 依赖的支持差异) | 打包后启动白屏 | 少依赖;设置自写;electron-vite 的 `externalizeDeps` 配置验证;每次改依赖都跑一次打包冒烟 |
| R-19 | **AI 生成代码的"看起来对"**:未实际跑过 | 笔试最忌讳 | 每个功能提交前必须跑通对应测试;所有"完成"声明附验证证据;测试结果如实写进 `TEST_REPORT.md`,失败的也写 |
